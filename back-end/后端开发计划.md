# 后端开发计划（待审核）

> 技术栈：Java 21 + Spring Boot 3.3.x + MyBatis + MySQL 8。原型阶段不写代码，本文供你审核。
> 目标：先把后端接口全部跑通（用 Swagger/Postman 自测），再做小程序联调、最后做后台前端联调。

---

## 1. 技术选型

| 项 | 选择 | 说明 |
|---|---|---|
| JDK | Java 21 (LTS) | 用 record/switch 模式等新特性需注意 MyBatis 映射仍用普通类 |
| 框架 | Spring Boot 3.3.x | 与 Java 21 兼容；Jakarta 命名空间 |
| 构建 | Maven | 单模块工程（小项目无需多模块） |
| ORM | **MyBatis**（mybatis-spring-boot-starter 3.0.x） | XML Mapper；分页用 PageHelper；用 MyBatis Generator 自动生成基础 CRUD，再手写业务 SQL |
| 连接池 | HikariCP（默认） | |
| 鉴权 | **JWT + 拦截器**（轻量，不引 Spring Security） | 双端两套 token：admin / student；ThreadLocal 存当前登录上下文 |
| 微信登录 | code2session（jscode2session）换 openid | 需配置 appid/secret |
| 参数校验 | jakarta validation（@Valid） | |
| 接口文档 | springdoc-openapi（Swagger UI） | 自测/给前端看 |
| 文件存储 | 抽象 StorageService：本地实现(开发) / 阿里云 OSS(生产) | 视频走**私有 + 签名 URL**，鉴权后下发 |
| 工具 | Lombok、Hutool（可选）、logback | |

### 需你拍板的 3 个决策

1. **ORM 写法**：纯 MyBatis（XML，可控、贴合你的要求）✅推荐 vs MyBatis-Plus（少写大量 CRUD 模板）。
   - 你明确说"用 mybatis"，我默认**纯 MyBatis + Generator + PageHelper**；若想省 CRUD 代码可改 MyBatis-Plus，告诉我。
2. **鉴权**：轻量 JWT+拦截器 ✅推荐（小项目够用、上手快） vs Spring Security（更标准、更重）。
3. **微信 appid/secret 与 OSS**：这些密钥你提供后我用环境变量/配置注入（不硬编码）。开发期可先用本地存储 + Mock 登录跑通。

## 2. 工程结构（分层）

```
back-end/
├─ pom.xml
└─ src/main/
   ├─ java/com/dance/studio/
   │  ├─ DanceStudioApplication.java
   │  ├─ common/            # 通用
   │  │  ├─ Result.java / PageResult.java     统一返回体
   │  │  ├─ BizException.java / GlobalExceptionHandler.java
   │  │  ├─ enums/          状态枚举(BookingStatus、RedeemStatus…)
   │  │  ├─ constants/      配置键、错误码
   │  │  └─ util/           JwtUtil、ContextHolder、DateUtil
   │  ├─ config/            MyBatisConfig、WebMvc(拦截器注册)、CorsConfig、SwaggerConfig、StorageConfig
   │  ├─ interceptor/       AdminAuthInterceptor、StudentAuthInterceptor
   │  ├─ entity/            与表一一对应(Generator 生成)
   │  ├─ mapper/            *.java + resources/mapper/*.xml
   │  ├─ dto/               入参(Req)
   │  ├─ vo/                出参(Resp)
   │  ├─ service/ + service/impl/   业务逻辑(事务边界在此)
   │  └─ controller/
   │     ├─ admin/          后台接口 /api/admin/**
   │     └─ mp/             小程序接口 /api/mp/**
   └─ resources/
      ├─ application.yml / application-dev.yml
      └─ mapper/*.xml
```

### 全局约定
- **统一返回**：`Result<T>{ code, message, data }`；分页 `PageResult<T>{ list, total, page, size }`。
- **错误码**：0 成功；4xx 业务错误（如 1001 课时不足、1002 已满员候补、1003 重复签到…）。
- **鉴权**：`/api/admin/auth/login`、`/api/mp/auth/login` 免登录；其余按前缀进对应拦截器，解析 JWT → 写入 `ContextHolder`（当前 adminId/studentId、storeId）。
- **store_id**：从登录上下文取，默认门店 1；所有查询带 store_id（多门店预留）。
- **时区**：Asia/Shanghai；时间字段 DATETIME。
- **金额/积分/课时**：积分课时用 INT，金额 DECIMAL(10,2)。

## 3. 核心领域服务（事务/并发关键，重点保障）

| 服务 | 关键职责 | 并发/一致性要点 |
|---|---|---|
| **AccountService** | 充值（建批次+流水+缓存）、签到扣课时（批次 FIFO 扣 remaining）、约课冻结/解冻、积分增减 | 流水 `*_log` 与缓存 `student.*` **同事务**；扣减用 `UPDATE…WHERE remaining>=? ` 防超扣 |
| **BookingService** | 约课（校验时间窗/余额/容量→冻结课时→排队候补）、取消（6h 规则退/扣）、候补自动递补 | 容量扣减用行锁/乐观锁：`UPDATE schedule SET booked_count=booked_count+1 WHERE booked_count<capacity`；唯一键防重复约课 |
| **CheckinService** | 扫码/代签：校验约课单+时间窗→课时正式扣减→加签到积分→写签到 | 唯一键 `checkin.booking_id` 防重复签到；一事务 |
| **RedeemService** | 抓娃娃机（从 claw 池随机**必得**1件→扣积分+锁库存+建发放单）、指定兑换、审批通过/驳回（驳回退积分+回库存）、物流流转 | 库存扣减 `UPDATE goods SET stock=stock-1 WHERE stock>0`；积分先冻结后结算 |
| **VideoService** | 解析可见名单（已签到/已约课/指定）→鉴权→生成带时效签名 URL | 鉴权在后端，绝不暴露原始地址 |
| **ConfigService** | 读业务规则（带缓存），所有规则取自 config 表 | 规则变更即时生效 |

**定时任务（Spring @Scheduled）**：
- 课时/积分过期（按 batch.expire_at / points_expire_days）
- 课次状态流转：到点 `open→finished`
- **爽约判定**：课次结束后，`booked` 未签到 → `noshow` + 扣冻结课时
- 临期/课时不足/上课提醒（写 notification，后续接订阅消息）

## 5. 开发顺序（分阶段，每阶段自测通过再进下一阶段）

| 阶段 | 内容 | 产出/验收 |
|---|---|---|
| **P0 脚手架** | Maven 工程、application.yml、Result/异常、JWT+拦截器、MyBatis+Generator 生成 20 表实体/mapper、Swagger、双端登录、文件上传 | 能登录拿 token、Swagger 可访问 |
| **P1 基础数据** | config 读写、dance_type/level/course/teacher CRUD | 后台字典与课程可维护 |
| **P2 学员+账户** | student CRUD、充值(批次)、积分手动增减、流水查询、AccountService | 充值/扣减流水与余额一致 |
| **P3 排课** | schedule CRUD + 冲突检测 | 周视图数据、冲突拦截 |
| **P4 约课+签到** ★难点 | booking 约课/取消/候补递补、checkin 扫码/代签、爽约定时任务 | 约课锁定→签到扣减→取消退/扣 全链路正确 |
| **P5 手办+乐园** | goods CRUD(两类)、claw 抓取(必得)、redeem 兑换、审批/驳回/物流 | 积分冻结/退回、库存不超卖 |
| **P6 小程序聚合** | mp/home、my-goods、videos(权限+签名)、notifications | 学员端所需聚合接口齐 |
| **P7 看板+定时任务** | dashboard 统计、过期/状态流转/提醒 | 统计数据、定时任务生效 |

> P0~P5 为后端 MVP 主体；P4、P5 是事务/并发重点，会写单元测试覆盖。

## 6. 我会注意的工程细节
- 不硬编码密钥（appid/secret/OSS/DB 密码走 application-*.yml + 环境变量）。
- 余额变动一律"流水 + 缓存"同事务；库存/容量用条件 UPDATE 防并发超卖。
- admin 初始密码用 BCrypt 重置（P0 加一次性初始化或提供生成脚本）。
- 所有列表接口分页；查询带 store_id。
- 关键状态用枚举常量，避免魔法字符串。
